# plot_motor_image —— L4CAN「0x210 指令 → 电机层执行核查」出图引导

把一次 L4 车检的 CAN 日志，按**统一时间轴**画成 5 面板总图，用来核查
「FSD 下发的指令」→「VCU 转发给电机/驱动器的报文」→「电机/驱动器的反馈」是否对得上。

```
plot_motor_image/
├── plot_motor_image.py          # 参考程序（可直接换成别的解释器跑）
├── HOW_TO_DRAW.md               # 本文
└── 0x210_motor_level_execution_<日志戳>.png   # 出图结果，可直接对比历史轮次
```

---

## 1. 数据从哪来

`zlgcan_bridge` 把总线报文**按「方向 + CAN ID」分文件**落盘，一次运行一个时间戳目录：

```
zlgcan_bridge/log/20261006_173043/
├── fsd2vcu/0x210.log   # 工控机(FSD) 发到总线
├── fsd2vcu/0x301.log
└── vcu2fsd/0x181.log   # 从总线上收到的（VCU / 电机 / 驱动器 / 遥控器）
    ├── 0x201.log  0x401.log  0x402.log  0x469.log  …
```

一行一帧，`(+ xx ms)` 是距**同 ID** 上一帧的间隔（肉眼可看周期与抖动）：

```
# id=0x469  dir=vcu2fsd  start=2026-10-06 17:30:54.281
2026-10-06 17:30:54.282  (      --  )  [8]  20 00 00 04 00 00 C8 EC
2026-10-06 17:30:54.292  (+  10.06ms)  [8]  20 00 00 04 00 00 C8 EC
```

**方向约定**：`fsd2vcu` = 工控机发出；`vcu2fsd` = 从总线收到。
所以「VCU→电机」的指令帧（0x469/0x201）和「电机→VCU」的反馈帧（0x401/0x181）
**都落在 `vcu2fsd/` 里**——靠 ID 区分谁发给谁，不靠目录。

| ID | 谁发给谁 | 周期 | 本轮用途 |
|---|---|---|---|
| `0x210` | FSD → VCU | 车检时 20ms | 纵向开度 + 横向正弦 |
| `0x301` | FSD → VCU | 50ms | 上线心跳 |
| `0x469` | VCU → EPS 转向电机 | 10ms | 转向速度指令 |
| `0x402` | VCU → EPS（伴随帧） | 10ms | 帧计数 + 两个摆动字段 |
| `0x401` | EPS → VCU | 50ms | 扭矩反馈 |
| `0x201` | VCU → BAMOCAR 驱动器 | 10ms | 扭矩给定 / 其它 REGID |
| `0x181` | BAMOCAR → VCU | 100ms | 实际转速 |
| `0x1E4` | RES 遥控器 → 总线 | 30ms | 发车按钮（Byte1=0x13） |

## 2. 30 秒上手

```bash
# ① 先体检（不出图，几秒出结论，强烈建议每次都先跑）
python3 plot_motor_image.py ~/yzl/WUTA_HIL_TEST/zlgcan_bridge/log/20261006_173043 --report-only --210-byte-order little

# ② 再出图（默认落到 log 目录的上两级：zlgcan_bridge 的上一级）
python3 plot_motor_image.py ~/yzl/WUTA_HIL_TEST/zlgcan_bridge/log/20261006_173043 --210-byte-order little
# 或指定输出
python3 plot_motor_image.py <log目录> -o /tmp/x.png

# ③ 一轮车检只关心最后那个窗口时，先把整轮画完再放大（x 轴秒数相对 0x210 首帧）
python3 plot_motor_image.py <log目录> --xlim 215 268 -o ..._zoom215-268.png
```

> **0x210 字节序（2026-10-06 起有变）**：FSD 发的 0x210 `Signal1/Signal2` 已从**小端**改为
> **大端（Motorola，高字节在前）**（`can_interface.cpp packControlFrame()`；
> `hil_test/config/protocol.yaml` 的 `signals.*.little_endian: false`）。
> 所以：**新日志（2026-10-06 20:0x 之后）默认按大端**；`20261006_173043` 及更早的日志是
> 旧的小端固件，必须加 `--210-byte-order little`，否则纵向/横向会被解成乱值
> （实测：中位 `FF 7F` 按大端读仍是 32767 看不出问题，但驱动窗口 `79 94` 会被读成
> 31124＝制动方向、横向 `E3 7F` 被读成 58239＝接近满右）。
>
> **别靠时间猜端序，要用「协议常量反解」验一下**：`controller.yaml` 的
> `inspection_throttle` 决定纵向 raw（`32767 + throttle*32768`）。例如
> `20261006_203325` 实测字节 `86 65` → 大端 34405 = `32767 + 0.05*32768` ✓（throttle=0.05），
> 小端则得 25990（-20.7% 制动）✗；同一轮横向读出 ±7562 raw 的**平滑 9.000s 正弦**，
> 小端读只会得到毛刺。两条都对上才敢定端序。
>
> **注意过渡期的日志会「半路换端序」**：`20261006_200234` 这一轮的 847s 里同时存在
> `FF 7F / 79 94`（旧小端）与 `7F FF / 94 79`（新大端）两种打包——中途重编重启过 FSD。
> 这种日志单张图只能选一种端序，另一种会画错；先按下面的「常值反解」判断主要时段属于哪种。

常用参数：

| 参数 | 作用 |
|---|---|
| `--report-only` | 只打印体检报告 |
| `--xlim A B` | 只画 `[A, B]` 秒（相对 0x210 首帧），把某个车检窗口放大 |

| `--drv-torque-regid 0x90` | 0x201 里扭矩给定的 REGID |
| `--drv-speed-regid 0x30` | 0x181 里实际转速的 REGID |
| `--title-prefix` / `--dpi` | 标题前缀 / 出图 dpi |

## 3. 版式规范（5 面板，自上而下就是信号流）

| # | 面板 | 数据 | 纵轴 | 颜色 | 标题句式 |
|---|---|---|---|---|---|
| ① | FSD 纵向 | 0x210 `Data1~2` **大端**（`--210-byte-order little` 读旧日志） | raw，刻度**按本日志实测值标**（中位值 / 驱动值 + 换算开度） | 蓝 `#1f77b4` | `FSD→VCU 纵向: N 段驱动（Ts1+Ts2），恒定 +x.xx% 开度（32767=中位）` |
| ② | FSD 横向 | 0x210 `Data3~4` **大端**（同上） | raw，刻度标 `中位` / `中位±幅值`，并标 `左/右 x.xx°(前轮)`、`x.x°(盘)` | 绿 `#2ca02c` | `…横向 = 正弦 ±7562 raw（前轮 ±5.7690°/方向盘 ±30.0°）、周期 9.000s，仅在 N 段驱动窗口内输出　[0=满左 ↔ 65535=满右]` |
| ③ | 驱动扭矩给定 | 0x201 `REGID=0x90` | % 额定（上限按实测峰值自适应） | 红 `#d62728` | 全零 → `…全程 0.00%（n 帧全零，覆盖 m/N 个驱动窗口）`；非零 → `非零 k 段 / m 帧，x.xx~y.yy%（raw a~b，32767=100% 额定），覆盖 m/N 个驱动窗口` |
| ④ | 驱动实际转速 | 0x181 `REGID=0x30` | % 额定（上限按实测峰值自适应） | 紫 `#9467bd` | 全零 → `…全程 = 0.00%（无衰减拖尾）`；非零 → `非零 m 帧 / k 段（最长 Ts），峰值 x.xx%（raw r），覆盖 m/N 个驱动窗口` |
| ⑤ | EPS 指令/反馈 | 0x469 速度字节（左轴）+ 0x401 扭矩字节（**右轴 `twinx`**） | 左轴 0x469 raw（`20`≈120rpm / `200`≈1200rpm / `250`≈1500rpm）；右轴 **Nm**（零点 `0x80`） | 橙 `#ff7f0e` + 青 `#17becf` | `VCU↔EPS: 转向速度指令恒为 200（≈1200rpm，不随正弦变化）；EPS 扭矩反馈零点 0x80=0Nm，车检段 a~b Nm（r=x.xx 与横向指令同相），静止段 ≈z Nm` |

版式硬性要求：

- **所有面板 `sharex=True` 且逐个 `ax.set_xlim(...)`**（`sharex` 只同步缩放，不会自动统一范围）；
  一张图里 5 个面板的 x 范围必须完全一致，否则各面板的竖线/窗口对不上（第一版就是这么废的）；
- 横轴只在最下面一张写：`时间 (s, 相对 0x210 首帧 HH:MM:SS.mmm)`；
- **t=0 统一取 0x210 首帧**，绝对时刻写进总标题；
- **刻度文字一律由本次数据算出来**，不要把某一轮的 `38009/+16%`、`±12.8 Nm` 硬编码进坐标轴；
- 每个驱动窗口的起止画一条灰点竖线，并给窗口加浅色底 + `k·Ts 完整/中断` 标注；
- 阶梯量一律 `ax.step(..., where='post')`，离散量再叠一层散点（**窄脉冲只能靠散点看见**）；
- **跨间隙必须真断线**：NaN 要插在**上一帧**的 x（见坑 #3），否则会出现跨百秒的假平台；
- 两个量纲不同时（0x469 raw vs 0x401 Nm）**用 `twinx()` 并显式标注两侧单位**，不要挤在同一根轴上；
- 图例放 `upper right`，`fontsize=9`；网格 `#dddddd`、`set_axisbelow(True)`；
- 面板高度比 1:1:1:1:1，`figsize=(16.5, 15.4)`，`tight_layout(rect=[0,0,1,0.982])`。

## 4. 报文解码约定（照这个抄，别自己猜）

```
0x210  FSD→VCU  DLC8   [0..1]=Signal1 纵向 **大端**（0x8665=34405=+5% → `86 65`；0x9479=38009=+16%）
                       [2..3]=Signal2 横向 **大端**（0x7FFF=32767=回正 → `7F FF`）
                       旧日志（≤2026-10-06 17:30）为小端，解码时加 `--210-byte-order little`
                       [4]=Signal3(1=正常)       [5]=finished
       raw→物理: 纵向 32767=0%，驱动半量程 32768（32767+throttle*32768）、制动半量程 32767；
       横向 **0=满左、65535=满右**（协议正式版），故 raw<32767=左打、raw>32767=右打，
       ±7562 raw ⇔ 前轮 ±5.7692° ⇔ 方向盘 ±30°（转向比 5.2）
0x469  VCU→EPS  DLC8   Data7(0基 6)=0xC8=200 速度指令（20→120rpm，250→1500rpm）
                       Data5(0基 4) 跳动，近似线性递增(R²≈0.87)、与横摆指令 r≈0.02，
                       Data8(0基 7) 与 Data5 强相关 → 二者是计数/校验对，不是物理量
0x402  VCU→EPS  DLC8   Data2~3(0基 1,2) = 16 位**大端**单调帧计数；
                       Data5/Data7 两个摆动字段；文档里没写，出结论前先按 DBC 复核
0x401  EPS→VCU  DLC8   Data2(0基 1) = EPS_Torque，**零点在 0x80**：物理值 = (raw-128)*0.1 Nm
                       协议文档写「signed 8-bit，-128~127 → -12.8~12.7 Nm」，但实测**不成立**：
                       同一段里字节是 0x81→0x80→0x7D→0x7B…（单调平滑，相邻帧最大跳变 6 LSB），
                       描述的是一个**连续量**；若按补码读，跨 0x80 就会出现 -12.8 → +12.5 Nm
                       的 25 Nm 瞬时跳变（物理上不可能）。故零点是 0x80，量程 ±12.7 Nm。
                       `--eps-torque-encoding signed` 可切回旧画法对照。
                       Byte1(0基 0) 有两种子型 0x10 / 0x20（本轮 218.2s 处切换），先别当物理量用
0x201  VCU→驱动器 DLC8 **Data1 = REGID，同 ID 复用！**
                       REGID 0x90 → Data2~3(0基 1,2) 小端**有符号** = TORQUE_CMD（32767=100%）
                       REGID 0x3D → 另一个量（样例②里有 2100 帧，恒 25648）
0x181  驱动器→VCU DLC4 Data1 = 0x30(SPEED_IST)，Data2~3(0基 1,2) 小端**有符号** = 实际转速
0x1E4  RES      DLC8   Byte1: 0x11 遥控在线 / 0x13 发车按钮 / 0x10 急停
                       实测 Byte2~3 是**计数+反码对**（如 B8 A9 / B9 A8），别把计数当状态；
                       本轮还见到 0x15(862 帧) 等未在协议里定义的状态，先记着别下结论
```

**0x401 的坐标系（本轮踩到的最大一个坑）**：旧图把 EPS 扭矩画成「静止时钉在 -12.8 Nm、
车检时在 ±12.8 Nm 之间方波跳变、与横向指令无关」。按 `(raw-128)*0.1` 重画后：静止段
≈+0.1 Nm、车检段 -1.0~+0.7 Nm 且与转向正弦 **r≈0.63 同相** —— 结论完全反过来。
判据就是「相邻帧字节跳变」：真扭矩不可能 50ms 跳 25 Nm，所以跨 0x80 连续的那个量
必然以 0x80 为零点。**任何 8 位量在上图前都用一次「相邻帧差分」验坐标系。**


**0 基 / 1 基的坑（必须两种都算一遍）**：文档写「0x469 Byte6 = EPS_Command_Velocity」。
按 1 基算 Byte6 = 全 0（= 从未下发速度指令）；按 0 基算 Byte6 = 第 7 字节 = 恒 200（≈1200rpm）。
两种读法结论一致（**没有时变转向指令**）时才敢写进标题；不一致就先找 DBC 确认。
脚本的 `--eps-cmd-byte` 就是为这件事留的开关，`--report-only` 还会列出所有
「落在 20~250 区间内的常量候选字节」供对照。

## 5. 出图前必做体检（checklist）

1. `--report-only`：看每个 ID 的 **帧数 / DLC / 中位周期 / 最大间隔**；
2. **最大间隔**暴露「这个 ID 只在某些窗口才存在」——0x469/0x402/0x201 都不是全程广播；
3. 常值检测：报出来的 `恒定 200~200` 才是常值，别把常值当「跟随正弦」；
4. **REGID 分布**：0x201/0x181 先按 Data1 过滤再解码；
5. 量程自检：转速/扭矩百分比出现 199%、>100% 之类，八成是**没按有符号解**或**串了 REGID**；
6. **坐标系自检**：8 位量先看「相邻帧最大跳变」（脚本已打印 `相邻帧最大跳变=N LSB`）。
   若某字节跨过 0x80 时跳变接近 250 LSB，而物理量不可能瞬变，就说明零点在 0x80 而不是补码；
7. **多窗口逐段结论**：一轮日志里常有 2~4 次车检（含中断重来），每段都要单独判
   「FSD 下了什么 / VCU 有没有转发电机报文 / 电机有没有响应」，别把某一窗口的结论当全轮结论；
8. 相关性 `r`：判断指令是否跟着 9s 正弦走（|r|<0.1 就可以说「无关」）；
9. 出图后**一定要回读图片**确认（文字没压线、文件不是 0 字节）。

## 6. 踩过的坑（血泪清单）

| # | 坑 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | 忘设中文字体 | 标题全是方框 | `plt.rcParams['font.sans-serif'] = ['Noto Sans CJK JP', …]` |
| 2 | `sharex=True` 就以为时间轴统一 | 各面板横轴范围不同，「对齐时间」失效（第一版就是这么废的） | 每个子图都 `set_xlim(xmin, xmax)` |
| 3 | **阶梯线跨间隔保持** | 0x201 两窗口相隔 110s，`where='post'` 把末尾 76% 一路保持成 110s 的假平台 | `step()` 里插 `NaN` 断线（阈值 0.5s）。**注意 NaN 要插在上一帧的 x**：`where='post'` 会先补 `(x_next, y_prev)`，NaN 挂在 `x_next` 上时水平段两端仍有限，假平台照画（150635 的 4 个 76% 脉冲就这样变成 27s 平台） |
| 4 | 不同量纲画同一根轴 | 0x401 的 Nm 和 0x469 的 raw 混画，曲线挤成一条线 | 要么换算到同量纲，要么 `twinx()` 并**显式标注单位**（面板⑤ 现在是左 raw / 右 Nm） |
| 5 | 同 ID 多 REGID | 把 0x3D 的 25648 当成 78.27% 扭矩，脉冲统计全错 | 先 `b[0] == REGID` 过滤，`--report-only` 会打印 REGID 分布 |
| 6 | 有符号当无符号 | 0x181 的 `0xFFD8`(=-40) 被读成 65496 → 199.9% | 反馈量用 `s16le()` |
| 7 | 计数/校验字节当物理量 | 0x469 Data5 变化剧烈，很像「速度指令」；0x1E4 Byte2~3 的 `B8 A9/B9 A8` 像状态 | 看它与时间是否近似线性、与指令是否相关；近似线性 + 无相关 → 计数；逐字节看是否成对取反 |
| 8 | 0 基/1 基字节编号 | 文档 Byte6 与实测对不上 | 两种都算，结论一致才写死；用 `--eps-cmd-byte` 切换 |
| 9 | 输出文件异常 | 保存后读到 0 字节 | 保存后 `ls -la` + 回读图片确认 |
| 10 | 没有显示环境 | `plt.show()`/默认后端报错 | 脚本已 `matplotlib.use('Agg')`，且必须在 `import pyplot` 之前 |
| 11 | 大日志解析 | 用 pandas 猜分隔符容易崩 | 逐行正则（脚本里的 `LINE`），一行一帧 |
| 12 | 时间基准混乱 | 每张图 t=0 不一样，无法横向对比 | 固定 `t=0 = 0x210 首帧`，绝对时刻写进标题 |
| 13 | **0x210 字节序改版** | 旧日志按大端解：驱动窗口变成「全程 34s 驱动」、横向 ±32654 / 146 次零穿越；过渡期日志（如 200234）同一条日志里混着两种端序 | 2026-10-06 起 FSD 的大端固件为默认；**旧日志必须加 `--210-byte-order little`**。注意 `0x7FFF/0xFFFF/0x0000` 是回文值，两种端序读出来一样，核对端序要用 `0xBFFF` 这类值；最稳的是拿 `inspection_throttle` 反解纵向 raw 对一遍 |
