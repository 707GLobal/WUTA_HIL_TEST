# FSD HIL测试方案

## **1. 背景与目标**

HIL 使用\*\*真实 VCU（整车控制器）\*\*直接连接工控机：

- 工控机侧 `can_interface` 经 CAN 总线与真实 VCU 双向通信，收发行为与实车一致；
- VCU 侧 AMI（任务选择）/ RES（Go / 急停）/ 安全回路等为真实电气信号，测试其真实行为；
- VCU 驱动真实电机台架（电机 + 驱动器 + 编码器），编码器/车速反馈经 VCU 回传工控机，形成完整闭环。

意义：

- 在真车跑车前，用台架闭环暴露链路、协议、安全、执行机构层面的问题；
- FSD 决策 / 控制链路跑在真实工控机与真实 CAN 总线上，行为与实车一致；
- 协议未定前，测试框架先行搭建，协议确定后只改配置、不改测试代码。

## **2. 系统架构**

```Plain
┌────────────────────────┐        CAN 500k        ┌──────────────────────────┐
│  工控机（FSD 全套）      │◀──────────────────────▶│  真实 VCU（整车控制器）  │
│  mission_manager        │      can0 (USB-CAN)    │    ├─ AMI 任务选择        │
│  controller             │                        │    ├─ RES Go / 急停       │
│  localization / …       │                        │    ├─ 安全回路 / 车速反馈   │
│  can_interface          │                        │    └─ 驱动电机 / 转向      │
│  hil_test（测试程序）     │                        │            │             │
└────────────────────────┘                        ┌────────────▼──────────┐
                                                  │  电机台架（真实硬件）      │
                                                  │  电机 + 驱动器 + 编码器   │
                                                  └────────────────────────┘
```

关键设计点：

\- **VCU 为真实硬件**：HIL 测试验证的是工控机与真实电控的完整交互，不是模拟器；

\- **工控机本体即测试上位机**：FSD 与测试程序同机运行，\`hil\_test\` 在 \`can0\` 上另开 SocketCAN 套接字做**被动监听**（SocketCAN 支持同一接口多套接字，与 can\_interface 并存不冲突）；

\- **测试程序以被动监听为主**：解码 CAN 帧、断言协议/安全行为、落盘日志；注入仅限 ROS 侧（控制指令 / 状态话题）与可选的 CAN 故障注入（见 §4）；

\- **AMI / RES / 安全回路是 VCU 侧真实信号**：Go、急停、任务选择的测试需实际操作 VCU 输入（按键 / 开关）或使用 VCU 调试口，CAN 无法代替。

## **3. 分层测试框架（由浅入深）**

每层独立可跑，前一层通过后再进入下一层。

### **L0 链路自检**

| 检查项       | 方法                                            | 通过标准                  |
| --------- | --------------------------------------------- | --------------------- |
| CAN 接口    | `ip link set can0 up type can bitrate 500000` | 接口 up，无报错             |
| 节点上线      | 启动 can\_interface                             | 日志显示 device opened    |
| 心跳        | 监听 0x301                                      | 每 100ms 稳定一帧，Byte1=01 |
| VCU 在线    | 观察 VCU 侧周期性报文                                 | 按协议周期稳定到达             |
| fail-safe | 断开 VCU / 接口 down 后重启节点                        | 日志告警且无任何非零输出          |

### **L1 协议一致性（协议预留，配置驱动）**

\- 协议不写死在测试代码里，用 **dbc 或 YAML 配置**描述报文 ID / 字节序 / 信号位 / 定标 / 周期；

\- **工控机 → VCU 方向**：通过 ROS 注入已知输入（\`speed=2.0\`、\`angle=0.1\`、mission state 等），抓 CAN 帧解码，断言与配置期望一致；

\- **VCU → 工控机方向**：真实 VCU 发出固定报文（任务选择、急停、车速），断言 can\_interface 发布的 ROS 话题字段正确；

- 覆盖：定标与中心点（32767）、字节序、越界钳位、无指令时全零、急停时 controller 持续输出 `speed=0.0/angle=0.0` 全零指令。

### **L2 安全与状态联动（真实 VCU 信号）**

| 场景    | 注入 / 操作                   | 断言                                      |
| ----- | ------------------------- | --------------------------------------- |
| 启动门控  | VCU 未给 Go（RES 未触发）时注入控制指令 | 总线输出恒为零命令                               |
| Go 放行 | 实际操作 RES 给 Go             | 总线开始透传控制量                               |
| 急停优先级 | 实际触发 RES 急停 / 断开安全回路      | 速度强制清零，立即发布 `/system/emergency=true`    |
| 看门狗   | 断开 VCU（停止所有报文）            | 超时后发布急停，无残留使能                           |
| 车检流程  | VCU 触发车检（AMI 选择）          | 状态机按 README 流转，inspection\_result 上 CAN |

### **L3 电机闭环（真实 VCU + 台架）**

- 台架通电，VCU 使能驱动，车速经 VCU 回传 → `/localization/velocity`；
- 依次下发：恒速跟随 → 加减速斜坡 → 急停刹停（RES）；
- 指标：稳态误差、上升 / 响应时间、超调、急停刹停时间与距离；
- 注意事项：先断电跑 L2 验证门控与急停无误，再通电跑 L3。

## **4. 测试程序组成（\`hil\_test\` 模块）**

```Plain
hil_test/
├── config/
│   ├── hil_test.yaml        # CAN 设备、波特率、测试参数
│   └── protocol.yaml        # 报文 ID / 信号位 / 定标（协议敲定后填充）
├── src/hil_test/
│   ├── bus_monitor.py       # 被动监听 CAN 帧 + 日志落盘 + 周期/ID 统计
│   ├── protocol_loader.py   # 解析 protocol.yaml，编解码统一入口
│   ├── ros_injector.py      # 向 ROS 话题注入控制指令 / 状态（驱动 FSD 输入）
│   ├── fault_injector.py    # 可选：CAN 故障注入（急停帧 / 停发），需独立测试通道
│   └── report.py            # 测试结果汇总，生成 Markdown 报告
├── test/
│   ├── test_protocol.py     # L1 协议一致性（pytest）
│   ├── test_safety.py       # L2 安全与状态联动（pytest）
│   └── test_motor_hil.py    # L3 电机闭环（pytest，标记 slow）
├── scripts/
│   └── run_hil.py           # 分层执行入口：--level L0..L3
└── README.md                # 用法与验收标准
```

依赖：`python-can`（工控机安装）、pytest、can-utils（candump/cansend 调试）。

设计要点：

- `bus_monitor` 在 `can0` 上以只读套接字被动监听，不占用 can\_interface 的收发；
- `ros_injector` 驱动 FSD 输入（等价于实车场景的决策层输入）；

\- VCU 侧真实信号（Go / 急停 / 任务）不走软件注入，由**人工操作**配合用例流程执行；

- `fault_injector` 仅用于故障注入场景，默认关闭，且建议用独立测试通道避免污染正常测试。

## **5. 开发实施步骤（里程碑）**

| 里程碑 | 内容                                                               | 环境               | 验收标准                    |
| --- | ---------------------------------------------------------------- | ---------------- | ----------------------- |
| M1  | 搭建 `hil_test` 框架：protocol\_loader + bus\_monitor + ros\_injector | 开发机 vcan0        | 能用 vcan0 抓帧，编解码配置可解析    |
| M2  | L0 + L1 用例跑通                                                     | 工控机 + 真实 VCU     | 心跳 / 链路用例绿；协议用例在配置驱动下绿  |
| M3  | L2 安全用例（含人工操作 Go / 急停）                                           | 工控机 + 真实 VCU     | 门控 / 急停 / 看门狗全部通过，且仅零输出 |
| M4  | L3 电机闭环                                                          | 工控机 + VCU + 电机台架 | 台架通电后闭环指标达标，输出报告        |

关键前置项：

- 协议敲定后填充 `config/protocol.yaml`（或提供 dbc），测试代码无需改动；
- 实现 `can_interface` 的收发编码（当前为 TODO），HIL 测试依赖其真实输出；
- 工控机安装 python-can、can-utils，确认 USB-CAN 适配器驱动与 `can0` 名称；
- VCU 上电联调：确认 AMI / RES / 安全回路接线与信号极性符合协议。

## **6. 台架安全注意事项**

- 台架通电前必须先通过 L2 全部用例（门控 / 急停 / 看门狗），确保故障方向收敛为"零输出"；
- 首次通电使用低速 / 低力矩档位，人工急停开关（RES）常备；
- 电机台架加机械限位与过流保护，编码器断线 / VCU 断线按急停处理；
- 看门狗超时按 SCS 要求（规则第四章 2.1）强制置急停，禁止残留使能；
- 测试期间任何时刻人工急停应优先于所有软件逻辑。
